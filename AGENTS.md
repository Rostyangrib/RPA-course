# Правила UI/UX «ОфисСнаб»

> Design like a product designer solving a workflow problem, not like an AI generating a Dribbble dashboard.

## Источник дизайн-системы

Веб-панель использует обычные HTML, CSS и JavaScript. Общие токены и стили находятся в [`rpa_course/web_assets/styles.css`](rpa_course/web_assets/styles.css). Образцы разметки находятся в [`index.html`](rpa_course/web_assets/index.html) и [`app.js`](rpa_course/web_assets/app.js). Ориентируйтесь на журнал обращений, панель фильтров, отчёт запуска и карточку обращения. Почтовые шаблоны относятся к отдельному каналу оформления.

## Токены и размеры

| Назначение | Токены и текущие значения |
| --- | --- |
| Поверхности | `--surface` `#2e2e30`, `--raised` `#333336` для раскрываемых панелей и наведения, `--scrim` `#15141788` для затемнения заднего плана диалога |
| Текст и линии | `--text` `#f1eff3`, `--muted` `#c2bfc7`, `--line` `#414044` для разделителей, `--control` `#605e64` для контура полей и кнопок |
| Акценты | `--accent` `#c4a8ff` для акцентного текста, `--selection` `#a475f0` для выбора и фокуса, `--brand` `#6137ad` и `--brand-ink` `#fff` для знака приложения |
| Статусы | `--status-success` `#a8d9bc`, `--status-attention` `#eac28e`, `--error` `#ffaab3`. Смысл передаётся подписью и поддерживается цветом |
| Базовый текст | `--font-family` Segoe UI с системным запасным шрифтом, `--text-base` 14 px, `--leading-base` 1,45 |
| Иерархия | `--text-ui` `.94rem` для элементов управления и строк таблицы, `--text-caption` `.86rem` для подписей, `--text-table-heading` `.84rem` для заголовков столбцов, `--text-page-title` `1.38rem` и `--text-page-title-narrow` `1.2rem` для заголовка страницы |
| Начертания | `--weight-control` 600 для кнопок, заголовков столбцов и тем писем, `--weight-emphasis` 650 для заголовков разделов, активных вкладок и раскрывающихся секций |
| Отступы | Шкала `--space-*` со значениями 4, 6, 8, 10, 12, 16 и 18 px. Между фильтрами 8 px, по горизонтали внутри кнопок и полей 12 px, внутри карточки 18 px на широком экране |
| Контуры | `--border-divider` и `--border-control` задают линии толщиной 1 px. Минимальная высота поля или кнопки `--control-height` 32 px. Радиусы `--radius-control` 16 px, `--radius-panel` 6 px, `--radius-date` 5 px и `--radius-brand` 7 px |
| Компоновка | `--shell-max` 1380 px и `--detail-max` 620 px. Контрольные ширины текущего интерфейса 860 и 520 px |

В текущей иерархии заголовок диалога занимает `1.12rem`, тема обращения `1.18rem`, заголовок секции `1rem`, заголовок пустого состояния `1.08rem`, название приложения `1.14rem`. Точные значения и исключения для отдельных элементов задаёт CSS.

## Переиспользуемые элементы

| Задача | Существующий образец |
| --- | --- |
| Страница и действия | `.shell`, `.page-heading`, `.page-actions` и `.button`. Акцент назначается основному действию рабочего сценария |
| Поиск и фильтрация | `.filters` с нативными `input` и `select`, `.period` и `.period-fields` для диапазона дат. Поля используют общий контур кнопок и сохраняют видимость полного значения |
| Быстрый выбор статуса | `.status-tabs` с кнопками, счётчиками и линией активного состояния. Выбор доступен через `aria-pressed` |
| Списки и журнал | Семантическая таблица в `.table-wrap`, компактные строки с горизонтальными разделителями, `.subject` для перехода к записи и `.pagination` внизу |
| Состояния | `.pill` для точки и подписи статуса, `.empty` для пустого списка, `.error-text` для ошибки и `.run-info` для результата запуска |
| Просмотр записи | Нативный `dialog`, `.detail-header`, `.detail-body`, `.metadata`, `.detail-section` и `.message-text`. Секции разделяются линиями. Длинные тексты и отчёты используют нативный `details` |

## Постоянные правила

- Начинайте с рабочего сценария сотрудника. Используйте плоскую компоновку, компактную типографику и ясную иерархию действий. Для списков используйте таблицы, строку фильтров и вкладки там, где они ускоряют поиск.
- Используйте общие токены и существующие компоненты на новых страницах. Сначала расширяйте общий компонент, если он нужен нескольким экранам. Новый CSS-файл или компонент добавляйте при самостоятельной задаче, которую не покрывает текущая архитектура.
- Добавляйте карточки, подложки, тени и скругления только тогда, когда они помогают отделить управляемый блок или состояние. Оформляйте одинаковые действия и состояния одинаково на всех страницах.
- Сохраняйте нативную семантику и работу с клавиатуры, видимый фокус, читаемые подписи и доступность данных на узком экране. Ошибки, загрузка и пустые списки должны подсказывать, что произошло и какое действие доступно.
- При систематизации сохраняйте внешний вид, разметку, бизнес-логику, API и обработчики. Сравнивайте интерфейс до и после на широком и узком экранах, в том числе таблицу с данными, пустой список, фильтры и карточку обращения.
